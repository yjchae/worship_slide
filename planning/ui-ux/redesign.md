# 예배 슬라이드 UI/UX 재설계

## 작업 흐름과 기능

1. **자료 준비**: 찬양 검색·수정·가져오기, 성경 검색·역본, 악보 OCR, PPT/PDF 가져오기, 동기화.
2. **콘티 구성**: 자료 담기, 순서와 그룹 정리, 빈 페이지·틀·미디어 추가, 가사·배경·코드 수정, 콘티 저장·불러오기.
3. **화면 디자인**: 공통 배경과 글꼴, 찬양·성경별 서식, 항목별 배경, 헌금송과 페이지 틀.
4. **발표**: 현재·다음 페이지 확인과 이동, 검은 화면, 슬라이드 편집, 시간·자동 넘김, 싱어·휴대폰·OBS·음성 제어.
5. **결과와 관리**: PPTX 저장, 모니터 선택, 테마, 업데이트, 진단 로그.

## 구조 원칙

- 상위 이동은 **콘티 준비 / 발표 보기** 두 단계로 구분한다. 발표 시작과 종료는 어느 단계에서도 찾을 수 있게 유지한다.
- 준비 화면은 **콘티 순서**와 **자료 찾기**를 독립된 영역으로 두고, 찬양과 성경은 자료 찾기의 하위 탭으로 묶는다. 검색 결과를 담거나 끌어 콘티 순서를 구성한다.
- 빈번한 추가·그룹 작업은 콘티 가까이에 두고, 새 콘티·저장·불러오기와 일괄 입력은 콘티 관리 메뉴로 모은다.
- 디자인은 작업을 가리지 않도록 기본적으로 접고, 공통·찬양·성경을 펼쳐 조정한다. 선택된 항목에 따라 기존 문맥 전환을 유지한다.
- 발표 화면은 현재 화면과 순서 이동을 중심으로 유지하며, 부가 제어는 기능별로 묶어 발표 중 실수를 줄인다.
- 삭제·초기화처럼 드물고 영향이 큰 작업은 일반 검색 조작과 분리한다. 기존 확인과 되돌리기는 유지한다.

## 적용 범위와 후속 검증

메인 준비 화면의 자료/콘티 영역과 관리 메뉴를 정리하고, 발표 보조 기능을 다음 슬라이드·시간 관리·관객 화면·메모와 메시지로 묶었다. 좁은 창에서는 상단 도구를 가로로 이동하고 슬라이드 편집기의 캔버스와 속성을 전환한다. 가사 편집 도구도 가로로 이동할 수 있다. 640×480 메인 화면과 800×600 편집 창을 위젯 테스트로 확인한다. 다양한 글자 배율과 실제 운영 환경의 화면 검증은 추가로 필요하다. 기존 단축키와 저장 형식, 발표 동작은 유지한다.

## 데스크톱 확인

macOS 실제 창을 800×600으로 줄여 기본·130%·160% 글자 배율의 준비 화면과 가사 편집을 확인했다. 큰 글자에서 가사 편집 머리글을 두 줄로 나누고 언어 추가를 아이콘으로 정리했다. 작은 창의 헌금송 편집은 미리보기와 설정을 전환하고 OBS 디자인은 세로로 배치한다. 800×600과 큰 글자에 대한 위젯 테스트는 슬라이드·가사·헌금송·OBS 편집 창을 확인한다. 그 외 창 및 Windows 실기 검증은 아직 하지 않았다.

추가 실창 확인: macOS 800×600에서 슬라이드 편집(캔버스·속성), 페이지 틀 관리, 헌금송 디자인, 항목 배경, OBS 디자인, 콘티 글 입력, 유튜브 페이지, 콘티 가사 편집 및 발표 보기를 열어 확인했다. OBS 미리보기는 설정이 아래에 있음을 볼 수 있도록 최대 너비를 제한했다. Windows는 별도 임시 브랜치의 CI에서 UI 위젯 테스트와 배포 빌드를 통과했다. 실제 Windows 데스크톱 상호작용은 이 환경에 Windows 화면이 없어 확인하지 못했다.

추가 보조 창 확인: macOS 데스크톱 테스트 화면에서 800×600·글자 160% 조건으로 코드 입력·조 변경·색상 선택·동영상/음악/유튜브·악보 가사·빠른 수정·설교 제목·PIN·콘티 입력·빈 틀 관리·동기화·콘티 저장·곡 변경 확인을 열었다. 코드/조/동기화의 긴 내용을 스크롤하도록 하고, 악보 가사 창의 동작 버튼을 고정했으며, 미디어 시간 표시와 설교 미리보기 크기를 조정했다. 테스트 화면은 가짜 데이터로 열었고 앱의 설정을 저장하지 않았다. 다양한 경고·오류·연결 상태와 모든 보조 창의 실제 화면을 망라한 검증은 아직 아니다.

보조 창 추가 확인: 테스트 데이터로 800×600·글자 160% 데스크톱 창에서 PPT 가져오기 결과, 클라우드 오류, 그룹 만들기, LibreOffice 설치 안내도 열어 보았다. 클라우드 오류는 내부 예외 유형과 경로 대신 사용자에게 필요한 메시지를 표시한다. 연결된 실제 클라우드 목록과 모든 오류·진행 상태는 확인하지 못했다.

연결된 클라우드 추가 확인: 실제 macOS 테스트 창에서 저장된 연결을 읽어 콘티 26개의 목록을 표시했다. 실제 데이터의 받기·삭제는 실행하지 않았다. 모의 서비스와 800×600·글자 160% 위젯 테스트로 긴 이름, 목록 오류, 갱신 요청의 역순 완료, 받기 취소·실패, 삭제 진행·실패를 확인했다. 오래된 목록 요청이 최신 결과를 덮지 않도록 하고 항목별 받기·삭제 진행 문구를 추가했다. 최신 변경은 Windows 실기 또는 Windows CI에서 다시 실행하지 않았다.

발표 디자인 리본 개선: 공통·찬양·성경의 설정을 기능별 하위 탭으로 나누고, 폭이 부족한 설정에는 가로 스크롤바와 좌우 이동 버튼을 제공한다. 가사·성경 본문·제목 크기와 보조 크기 비율은 1 단위 버튼과 직접 입력으로 조정한다. 640×480 마우스 이동과 800×600·글자 160% 기능 탭 및 크기 입력은 위젯 테스트로 확인했다. 이번 변경은 실제 Windows 데스크톱에서 확인하지 않았다.
