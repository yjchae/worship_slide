# 예배 슬라이드 UI/UX 재설계

## 작업 흐름과 기능

1. **자료 준비**: 찬양 검색·수정·가져오기, 성경 검색·역본, 악보 OCR, PPT/PDF 가져오기, 동기화.
2. **콘티 구성**: 자료 담기, 순서와 그룹 정리, 빈 페이지·틀·미디어 추가, 가사·배경·코드 수정, 콘티 저장·불러오기.
3. **화면 디자인**: 공통 배경과 글꼴, 찬양·성경별 서식, 항목별 배경, 헌금송과 페이지 틀.
4. **발표**: 현재·다음 페이지 확인과 이동, 검은 화면, 슬라이드 편집, 시간·자동 넘김, 싱어·휴대폰·OBS·음성 제어.
5. **결과와 관리**: PPTX 저장, 모니터 선택, 테마, 업데이트, 진단 로그.

## 구조 원칙

- 상위 이동은 **콘티 준비 / 발표 보기** 두 단계로 구분한다. 발표 시작과 종료는 어느 단계에서도 찾을 수 있게 유지한다.
- 준비 화면은 **콘티 순서**와 **자료 찾기**를 독립된 영역으로 두고, 찬양과 성경은 자료 찾기의 하위 탭으로 묶는다. 검색 결과를 담거나 끌어 콘티 순서를 구성한다.
- 빈번한 추가·그룹 작업은 콘티 가까이에 두고, 새 콘티·저장·불러오기와 일괄 입력은 콘티 관리 메뉴로 모은다.
- 디자인은 작업을 가리지 않도록 기본적으로 접고, 공통·찬양·성경을 펼쳐 조정한다. 선택된 항목에 따라 기존 문맥 전환을 유지한다.
- 발표 화면은 현재 화면과 순서 이동을 중심으로 유지하며, 부가 제어는 기능별로 묶어 발표 중 실수를 줄인다.
- 삭제·초기화처럼 드물고 영향이 큰 작업은 일반 검색 조작과 분리한다. 기존 확인과 되돌리기는 유지한다.

## 적용 범위와 후속 검증

메인 준비 화면의 자료/콘티 영역과 관리 메뉴를 정리하고, 발표 보조 기능을 다음 슬라이드·시간 관리·관객 화면·메모와 메시지로 묶었다. 좁은 창에서는 상단 도구를 가로로 이동하고 슬라이드 편집기의 캔버스와 속성을 전환한다. 가사 편집 도구도 가로로 이동할 수 있다. 640×480 메인 화면과 800×600 편집 창을 위젯 테스트로 확인한다. 다양한 글자 배율과 실제 운영 환경의 화면 검증은 추가로 필요하다. 기존 단축키와 저장 형식, 발표 동작은 유지한다.

## 데스크톱 확인

macOS 실제 창을 800×600으로 줄여 기본·130%·160% 글자 배율의 준비 화면과 가사 편집을 확인했다. 큰 글자에서 가사 편집 머리글을 두 줄로 나누고 언어 추가를 아이콘으로 정리했다. 작은 창의 헌금송 편집은 미리보기와 설정을 전환하고 OBS 디자인은 세로로 배치한다. 800×600과 큰 글자에 대한 위젯 테스트는 슬라이드·가사·헌금송·OBS 편집 창을 확인한다. 그 외 창 및 Windows 실기 검증은 아직 하지 않았다.
