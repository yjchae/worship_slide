# 기획서: 슬라이드 편집 창을 PowerPoint 처럼 — 캔버스 안 글 편집 · 상단 서식 리본 · 도형 · PPTX 요소 가져오기

## 목적
슬라이드 편집 페이지를 PowerPoint 처럼 "보이는 자리에서 바로" 고치게 한다. 최종적으로는 PowerPoint 에서 만든 PPTX 슬라이드를 요소(글 상자·도형·그림) 단위로 가져와 앱에서 계속 고칠 수 있게 한다.
(방법 = 캔버스 안 편집, 상단 리본, 도형 요소, PPTX → page_elements 변환. 목적 = 오른쪽 작은 입력칸에서 글을 쓰는 불편을 없애고, PPT 로 만든 페이지를 앱에서 고칠 수 있게 하는 것.)

## 범위
- 한다 (이번 기획 = 1~3단계):
  - 1단계: 캔버스 안 글 편집, 상단 서식 리본, 여러 요소 고르기(Shift/⌘·Ctrl+클릭)
  - 2단계: 도형 5종(사각형·둥근 사각형·타원·선·화살표), 채우기·투명도·테두리, 도형 안 글자, 글·도형 세로 맞춤, 끌어서 범위로 고르기, 맞춤(왼쪽·가운데·위 등)
  - 3단계: PPTX → 편집 페이지 가져오기(받을 수 있는 요소는 요소로, 나머지는 페이지 배경 그림으로)
- 다음 단계 (이번에는 하지 않지만 열어 둔다):
  - PPTX 내보내기 때 요소를 진짜 PPT 도형·글 상자로 내기(지금은 그림 한 장)
  - 기존 '외부 PPT 이미지' 항목의 페이지를 골라 '편집 페이지로 바꾸기'
  - 회전 손잡이와 회전 요소 받기, 문단마다 다른 정렬, 줄 간격 조절
  - PPT 에 심은 글꼴(`eot_font.py`)을 편집 창에 올리기
- 하지 않는다:
  - 표·차트·SmartArt·WordArt 효과·그라데이션·그림자·3D 를 편집 요소로 만들기
  - 애니메이션 편집, 마스터·레이아웃 편집
  - 관객 화면 렌더러 네 곳(미리보기·macOS·Windows·PPTX)의 편집 페이지 처리 변경 — 계속 구운 PNG 한 장이다
  - 싱어·통역·확대·포인터 변경
  - 원본 PPT 와 이어 두고 다시 불러오기(편집 페이지는 원본과 끊긴다)
  - 사용자가 글꼴 파일을 추가하는 기능(CLAUDE.md 의 라이선스 원칙 그대로)

## 변경 설계

### 사용자 흐름
1. 새 글 상자: 리본 '글 상자' → 캔버스 가운데에 빈 상자가 생기고 **바로 편집 상태**가 된다(커서 깜빡임). 입력한 글이 실제 크기·글꼴로 보인다. 빈 곳을 누르거나 ESC 를 누르면 편집이 끝나고, 상자는 고른 상태로 남는다(ESC 를 한 번 더 누르면 고르기 해제). 비어 있는 채로 편집을 끝내면 지금처럼 점선 '글 상자' 자리표시로 남는다(지우지 않는다).
2. 있는 글 고치기: 상자를 더블클릭하면 누른 자리에 커서가 놓인다. 상자를 고른 상태에서 Enter·F2 를 누르면 편집을 시작하고 커서는 글 끝에 놓인다. 편집 중 드래그는 글자 고르기이고, 상자 옮기기는 테두리를 끌어서 한다. 편집 중에는 Delete·Backspace·⌘/Ctrl+A·화살표가 글자에 작동하고 요소를 지우지 않는다.
3. 서식:
   - 글자를 골랐으면 리본 서식은 그 글자에만 적용한다.
   - 커서만 있으면 다음에 칠 글자에 적용한다(Quill 기본 동작).
   - 상자만 골랐으면(편집 아님) 글 전체에 적용한다.
4. 도형: 리본 '도형 ▾'에서 종류를 고르면 가운데에 기본 크기로 생긴다(선·화살표는 가로선). 리본 '도형 서식'에서 채우기 색(없음 포함)·투명도·테두리 색(없음 포함)·두께(pt)를 바꾼다. 사각형·둥근 사각형·타원은 더블클릭이나 입력으로 안에 글을 쓰고, 글은 기본으로 가운데 정렬·세로 가운데다. 선·화살표에는 글이 없다.
5. 여러 개 고르기: Shift 또는 ⌘/Ctrl+클릭으로 더하거나 뺀다(1단계). 빈 곳에서 끌어 범위로 고른다(2단계). 고른 것은 함께 옮기기·삭제·복제·순서 바꾸기가 된다. 리본 서식은 고른 것 중 해당하는 종류에만 적용한다. 크기 손잡이는 하나만 골랐을 때만 나온다.
6. PPTX 가져오기(3단계): 가져오기 메뉴 'PPT 를 편집 페이지로 가져오기…' → 파일 선택 → 진행 창 → 결과 창('슬라이드 N장 중 편집 가능 M장, 그림으로 둔 요소 K개, 빠진 꾸밈 J곳, 없는 글꼴: …') → 콘티 끝에 파일 이름 그룹으로 담긴다. 각 페이지는 콘티 목록 태그 '편집'이고 연필로 연다.

### 1단계 — 캔버스 안 편집 + 상단 리본
- `page_canvas.dart`: `PageCanvas` 에 `hiddenId`(String?)를 추가한다. 편집 중인 요소는 캔버스가 그리지 않는다(글이 두 번 보이지 않게). 굽기는 늘 null 로 부른다.
- `page_editor_dialog.dart`:
  - 상태 `_editingId`(String?)를 둔다. 편집 중이면 그 요소 자리(`_canvas` :1209 덮개 대신)에 `QuillEditor` 를 얹는다. 이 편집기는 `PageCanvas` 와 같은 방식(요소 크기 × 1920/1080 논리 크기를 `FittedBox`/`Transform.scale` 로 줄임)으로 배치해 줄바꿈이 캔버스와 같게 한다. 글자 크기는 `PageCanvas.fontScale` 을 곱한 실제 값이고 `_previewScale` 은 쓰지 않는다.
  - Quill 문단·목록 스타일은 `pageTextSpan` 의 기본 TextStyle 과 똑같이 맞춘다. 줄 높이 1.2(`_previewBase`)는 빼서 캔버스와 같게 한다.
  - `onDoubleTap`(:1249) → 편집 시작(누른 자리에 커서). 편집 중 덮개의 끌기는 테두리 띠(약 6px)에서만 받는다.
  - `_onKey`(:802·816 부근): 편집 중이면 Delete·화살표·⌘/Ctrl+D 같은 요소 단축키를 넘기지 않는다. ESC 는 편집 끝내기다. Enter·F2 는 편집 시작이다.
  - 되돌리기: 편집 시작부터 끝까지가 한 묶음, 기록 한 번이다(지금 `_editSession` 규칙 그대로).
  - 리본: `_toolbar`(:996)를 두 줄로 만든다.
    - 줄 1 '삽입·정렬': 지금 버튼 그대로 + (2단계) 도형 ▾
    - 줄 2: 고른 것에 따라 바뀐다. 글 상자를 고르거나 편집 중이면 '글자 서식'이다 — 글꼴(`FontFamilyPicker` 재사용)·크기(입력 + 목록 + 한 단계 크게/작게)·굵게·기울임·밑줄·취소선·글자 색·정렬(상자 단위)·글머리·번호·서식 지우기. 아무것도 안 고르면 비활성.
  - Quill 도구줄 대신 리본 버튼이 `_quill.formatSelection`(편집 중) 또는 요소 일괄 적용(편집 아님)을 부른다. `QuillSimpleToolbar`(:1519)는 없앤다.
  - '상자 선택 상태의 서식 = 글 전체': 상자 기본값(fontSize·color·bold·fontFamily)을 바꾸고 Delta 에서 같은 속성의 직접 지정을 지운다. 기울임·밑줄·취소선·목록은 상자 기본값이 없으므로 Delta 전체 범위에 넣는다. 기존 '직접 바꾼 글자 N곳/모두 기본값으로'(:1640)는 없앤다.
  - 오른쪽 패널(:1407): 글 상자 칸(`_textProperties` :1502 전체)을 없앤다. 아무것도 안 고르면 페이지 이름·배경, 그림이면 그림 설정만 남는다. 글 상자를 고르면 '위치·크기(숫자)'만 보인다(없애도 된다 — 결정 항목 4).
  - 여러 개 고르기: `_selectedId` → `_selectedIds`(순서 있는 집합). 끌기·삭제·복제·순서는 집합 단위다. 손잡이는 하나일 때만 나온다.
- `page_rich_text.dart`: 바꾸지 않는다(렌더 결과 그대로라 `_renderVersion` 을 올리지 않는다). 목록 기호 위치는 편집 중(Quill 들여쓰기)과 캔버스('• ' 접두)가 다를 수 있다 — 위험 참고.
- 첫 작업은 **확인 실험(반나절 이내)**이다. 글자 여러 크기·두 글꼴·한글/영문/긴 줄 견본에서 Quill 편집기와 `Text.rich` 의 줄 수·높이를 비교한다. 줄바꿈 위치가 다르면 결정 항목 1의 B안으로 바꾼다.

### 2단계 — 도형
- `page_element.dart`: `final class PageShapeElement extends PageElement`
  - JSON 예: `{"type":"shape","id","rect":[x,y,w,h],"shape":"rect|round_rect|ellipse|line|arrow","fill":"#RRGGBB"|null,"fill_alpha":0~1,"stroke":"#RRGGBB"|null,"stroke_width":pt(540 기준, 0~40),"radius":0~0.5(둥근 사각형, 짧은 변 대비, 기본 0.1667),"flip_h":bool,"flip_v":bool, 글: "text","rich","font_size","color","bold","align","font_family","valign":"top|middle|bottom"}`
  - 선·화살표는 rect 의 대각선(flip 으로 방향)이고 글 필드를 무시한다. 화살표 머리는 끝점 하나이고 크기는 두께에 비례한다.
  - 글 필드는 `PageTextElement` 와 이름·규칙이 같다(`pageTextSpan` 을 그대로 쓰도록 공통 부분을 함수로 뺀다).
  - `fromJson` 에 `case 'shape'` 를 넣는다. 틀린 값은 기본값으로 둔다(채우기 흰색 등 — 개발이 정한다).
- `PageTextElement` 에 `valign`(기본 top) 키를 더한다. 없으면 top 이라 옛 페이지 모양은 그대로다.
- `page_canvas.dart`: `PageShapeElement` 분기를 더한다. `CustomPaint`(채우기 → 테두리) 위에 글을 놓고, 안쪽 여백은 PPT 기본값과 같은 좌우 0.1in·상하 0.05in 를 540pt 기준으로 환산한다. 글은 valign 대로 놓고, 넘치면 위아래로 삐져나온다(지금 글 상자와 같다). `_renderVersion` 은 그대로다 — 새 종류만 늘 뿐 옛 요소 그리기는 그대로다.
- `page_editor_dialog.dart`: 리본 줄 1에 '도형 ▾'를 둔다. 도형을 고르면 줄 2가 '도형 서식'(채우기·투명도·테두리 색·두께 + 글자 서식 묶음)이 된다. 선·화살표 손잡이는 양 끝 두 개다. 빈 곳 끌기로 범위 고르기, 맞춤(왼·가운데·오른·위·중간·아래, 슬라이드 기준·여러 개면 고른 것 기준)도 더한다.
- 새 도형 기본값: 채우기 흰색 불투명, 테두리 없음, 글 검정 40pt 가운데. 연달아 넣으면 마지막 도형 서식을 이어받는다(`newTextBox` 규칙과 같다).
- `pageAutoName`·넘침 측정은 도형 안 글도 센다.
- `.wsconti`(`_backgroundPathSlots` :770)·틀 저장은 고치지 않는다(경로 없음).

### 3단계 — PPTX → 편집 페이지
- Python `ppt_tool.py` 에 새 명령 `layout <pptx> <작업 폴더>`를 둔다. `.ppt` 는 기존 변환 경로로 먼저 pptx 로 바꾼다.
  - 출력: `{slides:[{index, hidden, aspect_ok, background_png, elements:[…page_elements 형식…], dropped:{picture_as_background:n, effects_lost:n, fonts_missing:[…]}}]}`
  - 좌표: EMU → 슬라이드 비율. 글자: pt × 540 / 슬라이드 높이(pt).
  - **두 번 굽기**: 요소로 바꾼 도형을 지운 사본 pptx 를 기존 굽기(`render_presentation_images`, `--no-animation`)로 구워 각 장을 `background_png` 로 쓴다. 마스터·레이아웃 그림·배경 그라데이션·표·차트·받지 않은 도형이 모두 여기에 들어간다.
- 받는 것(요소로):
  - 글 상자·자리표시자(placeholder)의 글
    - 글자 서식: 크기·굵게·기울임·밑줄·취소선·색(srgb·scheme+lumMod/lumOff 풀기)·글꼴(latin/ea, 테마 글꼴 +mj/+mn 풀기)

## 수용 기준

1단계
- [ ] 글 상자를 더블클릭하면 그 상자 자리에서 커서가 나타나고, 친 글이 캔버스 위 실제 글꼴·크기·색으로 보인다. 오른쪽 패널에는 글 입력칸이 없다.
- [ ] 리본 '글 상자'로 넣은 상자는 마우스로 다시 누르지 않아도 바로 입력된다.
- [ ] 편집 중 Delete·Backspace 는 글자만 지우고 요소는 그대로다. ESC 를 한 번 누르면 편집이 끝나고 상자가 고른 상태로 남는다. 한 번 더 누르면 고르기가 풀린다.
- [ ] 같은 글을 편집 상태와 편집이 아닌 상태로 번갈아 볼 때 줄바꿈 위치와 줄 수가 같다. 확인 견본: 24·40·96pt, Pretendard·NanumMyeongjo, 한글·영문 섞인 3줄 이상 — 목록 줄 제외.
- [ ] '완료'로 구운 PNG 와 편집 창 캔버스가 같은 줄바꿈이다(기존 굽기 테스트 통과).
- [ ] 글자 일부를 골라 리본 '굵게'를 누르면 그 글자만 굵어지고, 상자만 고른 상태에서 누르면 글 전체가 굵어진다. 그 뒤 직접 지정이 남지 않는다(Delta 에 bold 속성 없음, 상자 bold=true).
- [ ] 리본의 글꼴·크기·색은 커서 위치나 고른 글자의 지금 값을 보인다. 섞여 있으면 빈칸으로 보인다.
- [ ] 편집 한 번(시작~끝)은 ⌘/Ctrl+Z 한 번에 통째로 되돌아간다.
- [ ] Shift/⌘·Ctrl+클릭으로 고른 요소 3개가 함께 끌려 옮겨지고 Delete 로 함께 지워지며, ⌘/Ctrl+Z 한 번에 되살아난다.
- [ ] 1단계 이전에 만든 편집 페이지를 열고 아무것도 안 바꾸고 완료하면 같은 PNG 경로(같은 캐시 키)가 나온다.

2단계
- [ ] 리본 '도형 ▾'로 사각형·둥근 사각형·타원·선·화살표를 넣을 수 있다.
- [ ] 채우기 색·채우기 없음·투명도(0~100%)·테두리 색·테두리 없음·두께가 캔버스와 구운 PNG 에 똑같이 나온다.
- [ ] 사각형·둥근 사각형·타원은 더블클릭하면 안에 글을 쓸 수 있고, 글은 기본으로 가로·세로 가운데다. 세로 맞춤 위/가운데/아래를 바꿀 수 있다.
- [ ] 선·화살표는 양 끝 손잡이로 방향과 길이를 바꾼다. 더블클릭해도 편집 상태가 되지 않는다.
- [ ] 도형이 든 페이지를 저장하고 앱을 다시 켜 불러와도 도형·글·서식이 같다. `.wsconti` 로 내보내 다른 PC 에서 가져와도 같다.
- [ ] 도형이 든 페이지 JSON 을 1단계 이전 코드(`PageElement.listFromJson`)로 읽으면 예외 없이 도형만 빠진다(테스트로 고정).
- [ ] 빈 곳에서 끌면 걸친 요소가 모두 골라진다. 맞춤 '가운데'를 누르면 하나는 슬라이드 기준, 여럿은 고른 범위 기준으로 가운데에 놓인다.

3단계
- [ ] 16:9 PPTX(글 상자·제목 자리표시자·사각형·그림)를 가져오면 슬라이드 수만큼 편집 페이지가 파일 이름 그룹으로 콘티 끝에 담긴다. 각 페이지의 글을 캔버스에서 바로 고칠 수 있다.
- [ ] 위치·크기는 원본과 슬라이드 폭의 1% 안으로 같다. 글자 크기는 원본 pt × 540 / 슬라이드 높이 pt 와 ±0.5 안으로 같다. 견본: 13.333x7.5in, 10x5.625in 두 크기.
- [ ] 제목 자리표시자처럼 크기·색·글꼴을 마스터에서 물려받는 글이 원본 PowerPoint 에서 보이는 값으로 들어온다(견본 PPT 로 확인).
- [ ] 표·차트·SmartArt·회전 도형·그라데이션 도형이 든 슬라이드는 그 요소들이 배경 그림에 있다. 나머지는 요소로 들어온다. 결과 창에 그림으로 둔 개수가 나온다.
- [ ] 4:3 슬라이드는 편집 페이지로 만들지 않고 결과 창에 '16:9 가 아님 N장'으로 알린다.
- [ ] 없는 글꼴이 쓰였으면 결과 창과 편집 창에 그 글꼴 이름이 보인다.
- [ ] 가져온 페이지는 '원본 열어 수정' 메뉴가 없고(sourcePath null), 원본 PPTX 를 고쳐도 바뀌지 않는다.
- [ ] 기존 '외부 PPT 이미지' 가져오기(그림으로)는 결과가 이 기능 이전과 같다.

12. 가져온 배경 그림의 자리 — A: 페이지 배경(`SlideBackground.imagePath`, `page_images/` 사본) / B: 맨 뒤 그림 요소(전체 크기) · 추천: A. 눌러도 골라지지 않아 PowerPoint 마스터처럼 다룬다. 배경 갤러리가 모음 밖 경로를 보이는 방식은 확인 필요.

## 위험
- Quill 편집기와 `Text.rich` 의 글자 배치 차이: 줄 높이·문단 간격·목록 들여쓰기가 달라 편집을 시작·끝낼 때 글이 움직일 수 있다(목록 줄은 거의 확실히 다르다). 1단계 첫 실험에서 확인하고, 어긋나면 결정 1의 B.
- 옛 앱에서 도형 페이지를 편집하면 도형이 조용히 사라진다(호환 절 참고). 여러 PC 가 다른 버전을 쓰는 교회에서 생길 수 있다.
- 편집 중 끌기(글자 고르기)와 요소 옮기기 제스처가 부딪친다. 테두리 띠 판정은 기존 썸네일 제스처 테스트처럼 위젯 테스트로 고정해야 한다.
- 3단계 상속 풀기는 PPT 마다 예외가 많다(테마 색 변형, 언어별 글꼴 ea/cs, 자동 맞춤 lnSpcReduction). 견본 밖 PPT 는 크기·색이 조금 다를 수 있다. 결과 창 '원본과 다를 수 있음' 안내와 '그림으로 가져오기' 길을 그대로 남기는 것이 대비책이다.
- 두 번 굽기는 LibreOffice 또는 PowerPoint 가 필요하다(기존 render 와 같은 선택 의존성). 둘 다 없으면 3단계 기능을 막고 기존 설치 안내를 띄운다. 심은 글꼴·숨긴 슬라이드 쪽 수 문제는 기존 render 의 미확인 사항을 그대로 물려받는다.
- 시스템 글꼴 이름 찾기(한글·영문 이름), Windows 에서의 캔버스 편집기 IME(한글 조합) 동작은 미확인이다. Windows 는 PR CI 빌드로만 확인되니 사람이 직접 입력해 봐야 한다.
- `page_editor_dialog.dart` 가 이미 1,939줄이다. 리본·캔버스 편집기를 같은 파일에 넣으면 더 커진다. 리본은 `page_editor_ribbon.dart` 로 나누는 것을 개발에 권한다.
