## 2. 사실과 어긋난 서술

- **치명** `_onStagingReorder` 를 `_placeStaging` 이 "같은 일"로 대체한다는 FE:47 서술은 `_removeStagingWhere` 의 부작용을 놓침. home:4202~4219 는 항목을 빼면서 `_noSpacerUids`(앞 항목 표시까지 `remove(i-1)`)·`_mediaGroups`·`_itemGroups` 를 지운다. 즉 현재 끌어 옮기기는 **`_mediaGroups` 를 잃는다**(발표 중 재생 중인 동영상 묶음이 새 묶음으로 처리됨). FE 가 "group 을 직접 쓰는 방식"만 고치고 `_mediaGroups`·`_noSpacerUids`(옮긴 항목 자신의 표시, 원래 이웃의 표시) 보존은 언급 안 함. 4962~4972 는 `_noSpacerUids.remove(newIndex-1)` 한 줄만 하고 **옮기기 전 자리의 앞 항목 여백**은 `_removeStagingWhere` 가 해제(`!joined && i>0`) — 이 둘을 `_placeStaging` 이 다 재현해야 한다. 테스트 목록(§6)에 여백 케이스 없음.
- **중요** FE:12 "성경 `_addBibleItem` 이 `_previewStagingUid` 를 새 항목으로"는 맞음. 반면 `_addSongToStaging`(2842~2848)은 preview 를 안 바꿈 — 끌어 놓기 후 강조(`_flashInserted`)·스크롤 설계는 두 경로 모두 새로 만들어야 하는데 plan.md:44 는 `_flashInserted` 재사용으로 적음. `_flashInserted` 는 발표 보기 슬라이드 번호 기준(home:4139, 4090 "번호는 옮긴 뒤 최종 슬라이드 기준") — 편집 탭 행 강조는 별도 구현 필요. 재사용 불가에 가까움(미확인: 4139 이하 본문을 끝까지 읽지 않음).

## 3. 빠진 경로

### 3-1 치명
1. **발표 중 편집 탭 삽입·이동 시 보던 페이지** — plan 위험에 "키로 다시 찾기"로 고정이라 적혀 있으나 수용 기준 B 는 "발표 중 보던 슬라이드 유지" 한 줄뿐이고 **C(그룹 이동·접기·풀기·삭제)에는 없다**. 그룹 삭제(항목 삭제)로 보던 슬라이드가 사라지는 경우 처리(`_removeStagingWhere` 4949 경로는 clamp 만)와 `_slideInfoKey`(home:636) 재탐색 규칙이 없다. 발표 중 그룹을 삭제/풀기/이동하면 관객 화면 변동 가능. 발표 중 허용할지(막을지)부터 결정 필요(`_newConti` 는 막음).
2. **되돌리기 스택 `_undoSeq` 와의 충돌.** home:2523~2618: ⌘Z 는 `_deleteUndo` 와 `_moveUndo` 두 개만 `_undoSeq` 로 순서 비교(`_undoLastSlideEdit` 2614). 새로 생기는 되돌리기(끌어 담기 / 그룹 연산 / 역본 변경)가 이 스택에 안 들어가면 ⌘Z 가 **엉뚱한 옛 삭제/이동을 되돌린다**. 또 `_VoiceUndo.capture`(195~)는 `_itemGroups`·`_noSpacerUids` 등을 담지만 새 상태 `_emptyGroups`·`_collapsedGroups` 는 담지 않고 `_sameAs`(219)에도 없음 → 이동 undo 직후 빈 그룹이 사라지거나 되돌린 뒤 머리줄이 어긋남. 새 `_VoiceUndo` 필드 추가와 `_sameAs` 갱신이 설계에 없다. 편집 탭에서 ⌘Z 가 동작하는지(`_handleEditKey` 는 발표 보기 키)도 문서에 없다.
3. **뒤에 붙이기(`_appendConti`) 와 그룹 인접 합침.** home:5640 `_itemGroups.addAll(result.itemGroups)` 로 이름만 붙임. 기존 마지막 그룹이 "시작곡"이고 붙인 콘티 첫 그룹도 "시작곡"이면 **한 그룹으로 합쳐짐**. plan.md:83 "뒤에 붙이기에서 붙은 그룹 유지"와 충돌(이름 기준 모델의 한계). 또 `_emptyGroups`·`_collapsedGroups` 를 붙일 때 어떻게 하는지(콘티 불러오기=비움, 붙이기=유지?) 없음.
4. **저장 직전 빈 그룹 안내와 저장 흐름.** mockup 1-B "저장 후 한 줄 안내" — 저장 로직(`SaveContiDialog`, `saveConti(overwriteUid:)`)에서 빈 그룹 수를 어디서 세는지, 덮어쓰기 저장·'저장하지 않은 변경' 판정에 빈 그룹 생성이 영향을 주는지 없음. 빈 그룹만 만든 뒤 종료하면 경고 없이 사라짐.

### 3-2 중요
5. **그룹의 마지막 항목을 빼거나 지울 때 빈 그룹 운명.** 모델상 그룹 = 항목에서 파생이라 마지막 항목이 나가면 머리줄이 사라진다. 그런데 `_emptyGroups`(이름+앞 항목 uid)가 있으면 "빈 그룹 유지"로 갈 수 있음 → 사라짐/빈 그룹 유지 중 어느 쪽인지 전 문서 무언급. 앞 항목 uid 가 지워지거나 옮겨지면 빈 그룹 위치(FE 정의)가 어디가 되는지도 없음. 실사용 중 가장 자주 만날 케이스(그룹에서 곡 하나 빼기).
6. **자동 여백(`_noSpacerUids`).** plan·FE 는 R5 한 줄 + `_onStagingReorder` 규칙 인용. 새로 필요한 케이스: ① 접힌 그룹 끝에 놓기(자동 펼침 안 함 → 여백 규칙이 놓은 위치에 적용) ② 그룹 경계에서 "그룹 마지막 아래 절반 = 그룹 안" 삽입 시 그룹 마지막 항목의 여백 해제 ③ 곡 끝 여백이 있는 항목 뒤에 성경 여러 개 삽입 시 `_insertItemsAfterSlide`(3899)의 "넣은 마지막은 여백 없음·`hadSpacer` 이동" 규칙과 FE `_insertNewItems`(여백 표시 정리) 규칙이 **서로 다름**(발표 보기 삽입은 넣은 항목을 전부 noSpacer 로 하는데 FE 는 앞 항목 한 개만 해제). 두 경로의 여백 결과 차이는 문서화 안 됨 — 편집 탭에서 끌어 담으면 곡 사이에 여백 페이지가 들어가고 발표 보기에서 붙이면 안 들어감. 허용 가능한 차이인지 결정 필요.
7. **다중 선택.** 편집 탭 목록엔 다중 선택이 없어 v1 한 개씩(FE §3-3). 그러나 plan 수용 기준 C "곡·성경·PPT·빈·편집 페이지 항목 모두 넣고 뺄 수 있음" 은 한 개씩이면 충족. mockup 은 다중 선택 없음 — 이 모순은 없으나, **발표 보기 썸네일 다중 선택(복사/끌기)으로 들어온 항목의 그룹** 규칙은 이미 `_insertItemsAfterSlide` 가 하고, 편집 탭 트리가 다중을 못 하는 비대칭만 사용자에게 알릴 것.
8. **콘티 한번에 넣기(`_importContiText`, home:2851)·빈/편집/미디어 페이지 추가(`_addBlankItem` 2920 등, 고른 항목 뒤)·헌금송·`_addPage` 메뉴**의 그룹 상속 규칙 없음. 현재는 그룹 없이 들어가 "그룹 중간에 새 페이지"가 그룹을 **둘로 쪼갬**(고른 항목 뒤 = 그룹 가운데, 새 항목 그룹 없음 → 같은 이름 두 구간). 트리 UI 에선 매우 눈에 띄는 회귀. `_indexAfterSelectedItem` 경로도 `_insertItemsAt` 규칙(이웃 그룹 상속)으로 통일해야 한다는 서술 없음.
9. **곡 나누기(`_splitStagingItem`, 4221)·옮기기 후 `item_group` 이어받기** — 현재 구현은 이어받음(3500대, 4090대에서 spacerUid 에 그룹 복사). 트리의 `ContiItemRow` 계산이 이 부수 uid 를 올바르게 그룹에 넣는지 테스트 없음.
10. **음성 검색 삽입(3830) 그룹 상속**: 이미 "놓은 자리 항목의 그룹 / 그룹 마지막 뒤여도 앞 그룹". FE 가 resolveDrop 일관성 테스트를 넣겠다고 했으나 "두 함수를 같은 입력으로 비교하기 어려우면 주석"으로 후퇴 — 사실상 불일치 위험이 열려 있음. 편집 탭 resolveDrop 은 "그룹 마지막 **항목 아래 절반 = 그룹 안**", 발표 보기는 "그룹 마지막 뒤여도 앞 그룹"으로 같지만, 편집 탭에서 **그룹 마지막 다음에 그룹 없는 항목의 위 절반** = 밖이다. 같은 위치라도 UI 에 따라 다른 결과(같은 놓는 지점이 두 행 사이 경계). 목업 2-A·2-C 의 선 표시(들여쓰기 시작점으로 안/밖 구분)로 해결하는 설계인데 FE 는 행 절반 판정만 설명 — 선의 왼쪽 시작점을 판정에 쓰는지 불명.
11. **PPTX 내보내기·`exportPayload`**: 그룹 무관이라 변경 없음(BE 확인, `ppt_tool.py` 에 `item_group` 없음 — 맞음 FE·BE 일치). 단 역본 변경 후 PPTX 반영 테스트(BE §7-8-⑦)가 FE §6 에는 빠짐.
12. **`.wsconti`·클라우드 콘티**: `item_group` 만으로 호환 — OK. 그러나 `normalizeItemGroup`(12자) 와 새 그룹 이름 입력창 한도 "최대 12자"(mockup) 일치 확인, `.wsconti` 가져오기 시 인접 합침 규칙(3-3)과 **빈 그룹이 파일로 못 간다**는 점을 안내해야 함. "클라우드 콘티 다시 받기=덮어쓰기"에서 접힘·빈 그룹 초기화도 명시 필요.
13. **삭제 시 그룹 정리**: 항목 삭제 → `_removeStagingWhere` 가 `_itemGroups` 를 지우므로 파생 그룹은 자동 소멸. 그러나 (a) `_emptyGroups`·`_collapsedGroups` 정리, (b) mockup 1-D "그룹과 항목 삭제"의 삭제 → 되돌리기(콘티 전체 undo? `_VoiceUndo`?) 의 상호작용, (c) 삭제 도중 발표 중 현재 슬라이드가 삭제 대상이면? — 모두 설계 없음. 발표 보기 삭제 경로(`_deleteSlides`)는 슬라이드 키 기반 숨김이고 편집 탭 삭제는 항목 제거라 `_undoSeq` 스택에 안 들어감(3-1-2 와 연결).
14. **접기와 발표 보기 일관성**: FE 는 "발표 보기 접기 안 함"(OK). 다만 접힌 그룹의 슬라이드는 `_allSlides` 에는 그대로 있으므로 편집 탭에서 접힌 항목을 **고른 항목(`_previewStagingUid`)**이 접힌 그룹 안이면 선택 표시가 안 보임 — 처리 없음. 접힌 그룹 안의 `_slideInfoKey` 로 현재 슬라이드가 있을 때 '현재' 표시 어디에?
15. **접근성·키보드**: 목업 1-D/3-B 키보드 동작(↑↓, Enter, Tab) 요구가 있으나 FE·plan 수용 기준·테스트에 없음. 끌기를 못 하는 사용자 대안(위로/아래로 이동 메뉴, Enter 담기)이 목업에만 있어 구현 누락 위험.

## 4. 요구 3 해석 타당성

요구 3 원문(plan.md:11)은 "담은 성경 항목을 발표 보기에서 다른 역본으로 바꿔 표시". 해석 후보:
- (a) 본문 역본 교체(plan·FE·BE·mockup 모두 선택). 항목 내용을 재생성하고 저장되는 스냅샷.
- (b) 항목별 보조 역본(현재 전역). 현재 모델에 없음.
- (c) 표시 전용 임시 전환(저장 안 됨).

평가:
- (a) 는 타당하나 **"표시"라는 단어와 "저장·PPTX 에 새 역본 반영"(plan 수용 기준 A)이 충돌할 수 있다.** 사용자가 발표 중 즉석에 역본을 바꿔 보여 주기만 원했다면(예: 청중 요청) 교체가 콘티를 영구히 바꿔 부담이 되고, 저장하지 않으면 사라지는 "작업 콘티 메모리" 성격이 사용자에게 안 보인다. 한편 plan 은 (c)를 새 필드·렌더러 변경 필요로 제외(`SlidePageData` 는 reference 문자열 렌더만 하므로 임시 전환은 슬라이드 전송 시점에 치환하는 방식이면 렌더러 변경 없이 가능할 수도 있음 — 미확인, 검증 필요).
- 손글 소실: 본문 수정 이력이 없어(home:2365·2454 에서 `BibleStagingItem` 은 reference 고정, text 만 교체되는 편집) **손으로 고쳤는지 판별할 방법이 없다**. plan:63·mockup 4-C 가 "손으로 고친 본문이 있으면 확인창"을 약속하지만, 판별은 "옛 역본으로 다시 만든 본문과 비교"해야 하고 그 읽기가 실패하면 판단 불가 — 판별 규칙(비교 기준·공백/줄바꿈 정규화)이 문서에 없다. 구현 불가능한 수용 기준이 될 위험.
- 책 이름 대응: 66권 전제(`mapBookName`)와 역본마다 절 번호 다름(예: 시편 머리글절) — 일부 절만 있을 때 "있는 절만으로 바꾸고 안내"(mockup 4-D)와 BE:79·FE "모두 비면 중단"이 일치하는지. 이때 `reference` 의 절 범위를 새 역본에 있는 절로 줄이는지(예 `3:16-18` → 일부) FE 는 `_buildReference(ref.verses)` 그대로라 reference 는 원래 절을 표시하는데 본문은 일부만 — 불일치 가능. mockup 4-D 는 "3:18 은 이 역본에 없어 빠졌습니다"라 reference 를 줄이는 쪽으로 읽힘. 결정 필요.

BE:80·FE:91 이 인지는 하나 수용 기준·테스트에 없음.
