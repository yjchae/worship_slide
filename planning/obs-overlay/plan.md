## 0. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 문제 | 지금은 PPT 를 특정 배경색으로 띄워 OBS 에서 크로마키로 빼서 하단에 얹는다 → 넘기기 싱크가 어긋나고, 결국 OBS 쪽에서 찬양·말씀을 한 번 더 만들어야 한다 |
| 목표 | 앱에서 페이지를 넘기면 **OBS 자막이 바로 같이 넘어간다.** 바탕은 **투명**(크로마키 불필요). 내용은 관객 화면과 같다 |
| 방식 | 앱 안에 작은 HTTP 서버를 **앱이 켜 있는 동안 상시** 띄우고, OBS **브라우저 소스**에 `http://127.0.0.1:<고정 포트>/obs?k=<고정 키>` 를 한 번만 넣어 둔다. 갱신은 SSE |
| 서버 | **싱어(휴대폰) 서버와 따로 둔다** — 그쪽은 발표마다 켜지고 꺼지며 포트·키가 바뀐다. 이쪽은 한 번 설정하면 영영 같은 주소여야 한다 |
| 내용 | 1단계: 찬양 가사(원본·보조·추가 보조) · 성경 본문(+참조) · 설교 제목. 그림 페이지(PPT·편집 페이지)·미디어·빈 페이지·자동 여백은 **투명(아무것도 안 보임)** |
| 디자인 | 관객 화면 디자인과 **따로 둔 'OBS 자막 디자인'**(글꼴·크기·색·외곽선·그림자·반투명 띠·정렬·아래 여백). 방송 화면 하단 자막은 관객 화면과 크기·바탕 조건이 다르다 |
| 캔버스 | **1920x1080 투명 페이지 하나**에 자막을 아래 기준으로 그린다. OBS 소스 크기 = 캔버스 크기, 위치는 앱 설정에서 정한다 |
| 언제 나가나 | 기본: **발표 중(관객 창이 열려 있을 때)만**. 선택: '발표 창 없이도 내보내기'(방송 전용 예배) |
| 블랙아웃 | 기본: OBS 자막도 **같이 감춘다**(스위치로 끌 수 있음) |
| 플랫폼 | macOS·Windows 모두(순수 Dart `dart:io` 라 네이티브 코드 없음). 통역 화면(B)과 달리 macOS 전용이 아니다 |
| 바뀌지 않는 것 | 관객 화면·싱어·휴대폰·통역(B)·PPTX·콘티 저장 형식·DB 스키마(20) |

## 1. 목표 · 범위

### 1-1. 해결하려는 것 (사용자 상황)
1. **싱크**: 크로마키 방식은 PPT(또는 관객 창)를 OBS 가 화면 캡처로 잡는다. 이 앱의 관객 창을 캡처해도 되지만, 관객 화면 디자인(배경 그림·큰 글자·가운데 배치)이 방송 하단 자막에 맞지 않아 결국 별도 PPT 를 만든다 → 같은 찬양·말씀을 두 번 만들고 두 곳에서 넘긴다.
2. **이중 작업**: 콘티는 이 앱에서 이미 만들고 있다. OBS 자막이 콘티를 그대로 따라오면 '두 번째 작업'이 사라진다.
3. **크로마키 품질**: 키 색 주변 테두리·글자 안티에일리어싱 색 번짐이 생긴다(일반적인 크로마키 한계). 투명 바탕이면 생기지 않는다.

### 1-2. 1단계 범위
- OBS 자막 서버(상시, 고정 포트·고정 키, 기본 127.0.0.1 에서만 받음)
- OBS 출력 페이지 HTML 1개(`/obs`) + 글꼴 파일 제공(`/font/...`)
- 내용: 곡 가사 · 성경 · 설교 제목 페이지 · 문구가 든 빈 페이지. 나머지 종류는 투명
- 'OBS 자막' 설정 창: 켜기/끄기 · 주소 복사 · 연결 상태 · 디자인 · 미리보기 · '브라우저에서 열어 보기'
- 블랙아웃 따라가기 · 발표 전 내보내기 스위치
- 페이지 바꿈 짧은 페이드(끌 수 있음)

### 1-3. 이후 단계(1단계에 넣지 않음)
- **2단계**: 다른 PC 의 OBS 에서 받기(같은 망, 결정 Q3 에 따라 1단계로 당길 수 있음) · 주소 뒤 옵션으로 소스 여러 개(예: `&lines=main` 원본만, `&lines=sub` 보조만 — 언어별로 다른 자리에 얹기) · 곡 제목/구간 이름 작은 꼬리표
- **3단계(검토만)**: 그림 페이지(PPT·편집 페이지)를 OBS 에도 띄우는 옵션(전체 화면 그림 — 하단 자막과 성격이 달라 별도 소스 주소가 맞다) · OBS WebSocket 으로 장면 바꾸기 연동 · 세로(9:16) 방송용 배치
- 하지 않음: 코드(코드 가사)·발표자 메모·송폼 라벨·시계는 OBS 로 보내지 않는다(관객 화면에 없는 것)

## 2. 기존 기능과의 관계

| 기능 | 무엇 | OBS 자막과 겹치나 |
|---|---|---|
| 관객 화면 | 네이티브 창, 디자인 그대로 | 내용 원천은 같다. **그리는 곳·디자인이 다르다** |
| 통역 화면(B) | macOS 전용 세 번째 **물리 모니터 창**. 슬라이드 칸 + stt_translate 자막 칸(`display.html?net`) | 겹치지 않는다. B 는 '현장 모니터 하나에 슬라이드+통역 자막'이고, OBS 자막은 '방송 영상 위 투명 자막'. 단 **stt_translate 자막도 OBS 에 얹고 있다면 두 자막이 하단에서 부딪힐 수 있다**(B 설정 창 문구 "자막 언어·글자 크기는 통역 프로그램의 OBS 설정을 따릅니다" — 사용자가 이미 OBS 를 쓰는 것으로 보인다). 위치 조정은 사용자 몫이고, 설정 창에 '아래 여백' 칸으로 비킬 수 있게 한다 |
| 싱어 화면·휴대폰 | 가사만, 어두운 고정 배치, 휴대폰은 SSE | 전송 방식(SSE·마지막 JSON 기억)은 같은 꼴을 쓴다. 서버는 따로(§6 Q1) |
| `SlidePageData.forB` | B 에 보조를 본문으로 올림 | OBS 는 '어느 줄을 보일지'를 디자인에서 고른다(원본/보조/추가 보조 각각 스위치). forB 처럼 올리지는 않는다 |

## 3. 사용자 흐름

### 3-1. 처음 한 번 (설정)
1. 앱 바 '발표 시작' 옆 모니터 버튼 옆의 **'OBS' 버튼**(s1)을 누른다 → 'OBS 자막' 설정 창(s2)
2. **'OBS 자막 켜기'** 스위치를 켠다 → 상태 줄이 '켜짐 · 연결된 OBS 없음' 으로 바뀐다. 주소 칸에 `http://127.0.0.1:<포트>/obs?k=<키>` 가 보인다
3. **'주소 복사'** 를 누른다
4. OBS 에서 (메뉴 이름은 OBS 판·언어 설정에 따라 다를 수 있어 **미확인**):
   1. 자막을 얹을 장면을 고른다
   2. '소스' 목록 아래 **+** → **'브라우저'**(영문 'Browser') → 새 소스 이름(예: `찬양 자막`) → 확인
   3. 속성 창의 **URL** 칸에 복사한 주소를 붙여 넣는다. '로컬 파일' 체크는 끈다
   4. **너비 1920 · 높이 1080** 으로 맞춘다(OBS 캔버스가 다른 크기면 소스를 캔버스에 맞춰 늘린다 — 메뉴 이름 미확인, 대개 소스 우클릭 '변환' 쪽)
   5. 사용자 지정 CSS 칸: OBS 기본값에 바탕을 투명하게 하는 줄이 들어 있다고 알려져 있으나 **미확인**. 우리 페이지는 스스로 `background: transparent` 를 두므로 기본값을 그대로 두면 된다(지워도 된다 — 사용자 확인)
   6. 확인 → 소스를 자막 소스들 맨 위(목록 위쪽)로 둔다
5. 앱 설정 창 상태 줄이 **'켜짐 · OBS 1곳 연결됨'** 으로 바뀌면 끝(서버가 SSE 연결 수를 센다)
6. 디자인 탭(s3)에서 글자 크기·외곽선·띠·아래 여백을 맞춘다. **미리보기**(앱 안) 와 OBS 화면이 같이 바뀐다(설정을 바꾸면 지금 페이지를 다시 보낸다)

### 3-2. 매주 예배
1. 앱을 켠다(설정에서 켜 둔 상태면 앱 시작 때 서버도 켜진다)
2. OBS 를 켠다. **앱보다 OBS 를 먼저 켰다면** 페이지를 못 읽은 상태일 수 있다 → §8 R2. 페이지를 읽은 뒤에 앱을 껐다 켜는 것은 SSE 가 스스로 다시 붙는다
3. 콘티 → '발표 시작'. 넘길 때마다 관객 화면과 OBS 자막이 같이 바뀐다. 블랙아웃(B)하면 OBS 자막도 사라진다(기본)
4. 설교 중처럼 자막이 필요 없을 땐: 그 사이 페이지가 빈 페이지·그림 페이지면 저절로 투명. 아니면 OBS 에서 소스 눈 아이콘을 끄거나, 앱 설정 창(또는 발표 보기 칩 s6)의 **'OBS 자막 잠시 숨기기'**
5. 발표 종료 → OBS 자막은 투명

### 3-3. 방송만 하는 예배(관객 프로젝터 없음)
- 설정 창 '발표 창 없이도 내보내기'(기본 끔)를 켜면 **발표 보기 탭에서 고른 지금 페이지**가 OBS 로 나간다(발표 시작을 안 해도). 관객 창이 없으므로 블랙아웃은 이 상태에서 못 쓴다 → 대신 '잠시 숨기기'

## 4. 화면 구성 (UI 설계자용)

### s1. 앱 바 — OBS 버튼
- 위치: 앱 바 '발표 시작' 버튼 · 모니터 선택 버튼 옆(같은 묶음). 아이콘 + 짧은 글 `OBS`
- 상태 점(아이콘 오른쪽 위 작은 점): 꺼짐 = 없음 / 켜짐·연결 없음 = 회색 / 켜짐·연결 있음 = 초록 / 오류(포트 사용 중) = 빨강
- 툴팁: `OBS 자막 — 켜짐, OBS 1곳 연결됨` 등 상태 문장
- 누르면 s2

### s2. 'OBS 자막' 설정 창 — '연결' 탭
- 창 제목 `OBS 자막`, 탭 두 개 `연결 | 디자인`, 오른쪽 아래 `닫기`(설정은 바꾸는 즉시 저장, 확인 버튼 없음 — 미리보기가 OBS 와 같이 움직이게)
- 맨 위 줄: 스위치 **OBS 자막 켜기** + 상태 글 (`꺼짐` / `켜짐 · 연결된 OBS 없음` / `켜짐 · OBS 2곳 연결됨` / 빨강 `포트 8xxx 를 다른 프로그램이 쓰고 있습니다`)
- **주소** 칸(읽기 전용, 고정폭 글꼴) + `주소 복사` 버튼 + `브라우저에서 열어 보기` 버튼(기본 브라우저로 `…&preview=1` — 바둑판 바탕으로 투명 확인용)
- 접힌 '고급' 묶음:
  - 포트 숫자 칸 + `적용`(바꾸면 OBS 주소도 바뀐다는 경고 문구)
  - `키 새로 만들기` 버튼(확인창: "OBS 에 넣은 주소를 다시 넣어야 합니다")
  - (Q3 결정 시) 스위치 `같은 망의 다른 PC 에서 받기` + 켜면 사설 IP 주소 목록(`http://192.168.x.x:<포트>/obs?k=…`)과 방화벽 안내 한 줄
- '내보내기' 묶음:
  - 스위치 `블랙아웃하면 자막도 감추기`(기본 켬)
  - 스위치 `발표 창 없이도 내보내기 (발표 보기에서 고른 페이지)`(기본 끔)
  - 스위치 `설교 제목 페이지 내보내기`(기본 켬)
  - 스위치 `페이지 바뀔 때 페이드`(기본 켬)
- 맨 아래 접힌 'OBS 에 넣는 법' 안내(§3-1 4번 단계 요약, '메뉴 이름은 OBS 판마다 다를 수 있음')

### s3. 'OBS 자막' 설정 창 — '디자인' 탭
- 왼쪽(넓게): **미리보기** 16:9 — 바둑판(투명 표시) 또는 고른 예시 바탕 위에 자막. 바탕 고르기 칩 `바둑판 | 검정 | 밝은 사진`(밝은 바탕에서 외곽선이 보이는지 확인용). 미리보기 내용은 `지금 페이지`(있으면) 또는 예시 가사/예시 성경 토글 `찬양 예시 | 성경 예시`
- 오른쪽(폼, 기존 `style_fields.dart` 부품 재사용):
  - **글꼴**: `FontFamilyPicker` + 체크 `관객 화면 글꼴 따라가기`(기본 켬)
  - **줄**: 체크 `원본` `보조` `추가 보조`(기본: 원본·보조 켬 — 관객 디자인의 보조 표시 스위치가 꺼져 있으면 보조도 끔) · 성경 `참조 표시`(기본 켬) · 찬양 `곡 제목 표시`(기본 끔)
  - **크기**: 원본 글자 크기(pt, 1080 높이 기준) · 보조 % · 추가 보조 %(본문 대비)
  - **색**: 원본 · 보조 · 추가 보조 · 참조(`ColorField`)
  - **외곽선**: 색 + 두께(0 = 없음)
  - **그림자**: 켬/끔 + 색 + 흐림 정도
  - **띠**: 켬/끔 + 색 + 불투명도(0~100%) + 안쪽 여백 · 모양 `글 폭에 맞춤 | 화면 폭 전체`
  - **위치**: 정렬 `왼쪽 | 가운데 | 오른쪽` · 세로 기준 `아래 | 위` · 기준에서 떨어진 거리(1080 기준 px) · 좌우 여백
  - **최대 높이**: 화면 높이 대비 %(이걸 넘으면 글자를 줄인다, §5-3)
  - `기본값으로` 버튼
- 각 값 바꿀 때마다 미리보기와 OBS(연결돼 있으면)가 같이 바뀐다

### s4. OBS 출력 페이지 — 찬양 (1920x1080, 바탕 투명)
- 아래 가운데, 아래에서 일정 거리 위에 자막 덩어리 하나
- 덩어리 = [곡 제목(선택, 작게)] → 원본 줄들 → 보조 줄들 → 추가 보조 줄들. 줄은 **관객 화면 페이지의 줄 그대로**(원본 줄바꿈 유지), 폭을 넘는 줄만 자동 줄바꿈
- 덩어리 뒤 반투명 띠(선택), 글자에 외곽선·그림자
- 덩어리는 **아래 기준선에서 위로 자란다** — 줄 수가 페이지마다 달라도 아래 선이 고정
- 페이지 바뀜: 옛 덩어리 페이드 아웃과 새 덩어리 페이드 인이 겹쳐 지나간다(설정으로 끄면 즉시)

### s5. OBS 출력 페이지 — 성경
- s4 와 같은 덩어리. 맨 위 또는 맨 아래(UI 설계자가 정함, 추천 맨 위 작게)에 참조 `요한복음 3:16` — 관객 화면 `title` 과 같은 글
- 절 번호는 관객 화면 본문 글에 들어 있는 그대로
- 성경은 줄이 길어 대개 자동 줄바꿈이 많다 → 최대 높이를 넘으면 글자를 줄인다

### s6. 발표 보기 머리줄 칩 (작게)
- OBS 자막이 켜져 있을 때만 발표 보기 머리줄(또는 툴바 끝)에 `OBS ●` 칩. 누르면 `잠시 숨기기 / 다시 보이기` 토글(숨긴 동안 칩이 주황 `OBS 숨김`)
- 이유: 예배 중에 설정 창을 열지 않고 자막만 빨리 끌 수 있어야 한다

### s7. 투명 상태 (비교용 목업)
- 발표 전 · 발표 종료 · 블랙아웃 · 그림/미디어/빈 페이지 · 숨김 — 모두 **완전 투명**(아무것도 안 그림). 오류 글도 띄우지 않는다(방송에 나가므로)
- `&preview=1` 로 열었을 때만 바둑판 바탕 + 오른쪽 위 작은 상태 글(`발표 전`, `블랙아웃`, `그림 페이지 — OBS 에는 안 보임`)

## 5. 페이지 종류별 OBS 출력 규칙

### 5-1. 규칙표

| 지금 페이지(관객 화면 기준) | OBS 출력 | 근거 |
|---|---|---|
| 찬양 가사 | 원본·보조·추가 보조 중 디자인에서 켠 줄. 곡 제목은 선택 | 핵심 용도 |
| 찬양 — 빈 가사 페이지(곡 안 빈 페이지) | 투명 | 관객 화면도 비어 있다 |
| 성경 | 본문(+보조·추가 역본) + 참조 | 핵심 용도 |
| 설교 제목 페이지(`isSermon`) | 주제(본문) + 부제(보조 줄). 스위치로 끌 수 있음(기본 켬) | 방송 하단에 설교 제목이 뜨는 것은 흔하다. 부제는 번역이 아니라 내용이라 '보조 줄 끔'과 상관없이 보인다(관객 화면 규칙과 같다) |

| 빈 페이지(문구 있음) | 문구를 자막으로 | 관객 화면에 글이 보이므로 같게 |
| 자동 여백 | 투명 | 곡 사이 쉼 |
| 슬라이드 편집 페이지(구운 PNG) | **투명** (1단계) | 1920x1080 그림이라 하단 자막 자리에 얹으면 방송 화면을 덮는다. 글 상자 글만 뽑아 자막으로 낼 수도 있으나 배치·의미가 페이지마다 달라 1단계 제외 |
| 외부 PPT 그림 페이지 | **투명** (1단계) | 위와 같다. 그림 안 글을 알 수 없다 |
| 동영상·음악·유튜브 페이지 | 투명 | 영상은 OBS 가 따로 잡는다. 소리 중복 방지(B 와 같은 이유) |
| 배경 영상이 깔린 가사 페이지 | 가사만(영상 없음) | 배경 영상은 관객 화면 꾸밈 |
| 페이지별 글자 서식(`page_format`) | 무시 — OBS 디자인 그대로 | 싱어·B·휴대폰과 같은 규칙. 관객 화면용 강조라 방송 자막에선 일관성이 낫다 |
| 코드·메모·송폼 라벨 | 보내지 않음 | 관객 화면에 없는 것 |
| 블랙아웃 중 | 투명(기본) / 스위치 끄면 그대로 | §6 Q6 |
| 발표 전 | 투명(기본) / '발표 창 없이도 내보내기' 켜면 발표 보기 지금 페이지 | §6 Q5 |
| 발표 종료 후 | 투명 | 마지막 가사가 방송에 남지 않게 |
| 'OBS 자막 잠시 숨기기' | 투명 | s6 |
| 앱 종료 | OBS 페이지는 마지막 상태를 유지할 위험 → 서버가 닫히기 전에 '투명' 한 번 보낸다. 연결이 끊기면 페이지가 스스로 투명으로 | §8 R3 |

### 5-2. 데이터 흐름
- 관객 페이지 JSON(`SlidePageData`)에서 **필요한 칸만 뽑은 작은 JSON**(`ObsOverlayData`, 순수 함수 `obsOverlayFor(slide, page, config, state)`)을 만든다: `visible`, `kind`(`song`/`bible`/`sermon`/`text`), `title`, `lines: {main, sub, extra}`, `rev`. 스타일은 별도 `design` 메시지로(바뀔 때만)
- 보내는 곳: `_sendCurrentSlide` 끝(싱어·B 와 같은 자리 — 페이지가 바뀌는 모든 길이 지난다) + 블랙아웃·발표 시작/종료·설정 변경
  - `_sendCurrentSlide` 는 발표 전 발표 보기 탭에서 페이지를 고를 때도 불린다(`_goToSlide` → `_sendCurrentSlide`) — '발표 창 없이도 내보내기' 가 이 길을 그대로 쓴다
  - 관객 창 전송·가사 PNG 굽기(`_presentablePage`)를 **기다리지 않고** 보낸다(텍스트만이라 바로). 단 관객 창보다 먼저 바뀌는 것이 문제면 관객 창 전송 뒤로(§6 Q9)
- 서버는 마지막 JSON 을 기억해 새로 붙은 OBS 에 바로 준다. 같은 JSON 이면 다시 안 보낸다

### 5-3. 글자 맞추기 (OBS 페이지 안, 브라우저가 계산)
1. 줄은 관객 페이지 줄 그대로. 좌우 여백 안 폭을 넘는 줄만 줄바꿈
2. 덩어리 높이가 '최대 높이'를 넘으면 글자를 같은 비율로 줄인다(아래 한계 없음 — 잘리는 것보다 작은 게 낫다). 싱어 화면의 '자동 맞춤'과 같은 생각
3. 단위는 페이지 높이 기준(`vh`) — OBS 소스를 1920x1080 이 아닌 크기로 넣어도 비율대로 따라간다

## 9. 위험 · 미확인

| # | 내용 | 상태 · 대응 |
|---|---|---|
| R1 | 사용자가 찬양을 **PPT 그림 페이지**(외부 PPT 넣기)로 콘티에 담고 있다면 1단계 OBS 자막은 비어 보인다. 크로마키로 PPT 를 빼고 있다는 설명으로 보아 가능성이 있다 | **미확인 — 사용자 확인**. 폴더 가져오기(가사를 텍스트 곡으로)로 옮기면 해결. 아니면 Q10 3단계를 앞당긴다 |
| R2 | OBS 가 앱보다 먼저 켜져 페이지를 못 읽으면 **스스로 다시 읽지 않을 수 있다**(OBS 브라우저 소스의 실패 페이지 동작 미확인) | 앱 시작 때 서버 자동 켜기(Q14). 안내에 'OBS 소스 속성의 새로 고침' 을 적는다(버튼 이름 미확인). 페이지를 한 번 읽은 뒤의 끊김은 EventSource 가 다시 붙는다 |
| R3 | 앱이 강제 종료되면 마지막 가사가 OBS 에 남을 수 있다 | 페이지가 SSE 끊김(`onerror`)을 받으면 바로 투명으로. 정상 종료는 서버가 '투명' 을 먼저 보낸다 |
| R4 | OBS 브라우저 소스가 `body` 투명 바탕을 투명으로 합성하는지 | 널리 알려진 동작이지만 **미확인(사용자 PC 에서 확인)**. 1-d 에서 확인 |
| R5 | OBS(CEF)가 SSE(`EventSource`)·`@font-face`·CSS `-webkit-text-stroke`/`paint-order` 를 지원하는지 | 일반 Chromium 기능이라 될 것으로 보나 OBS 판에 따른 CEF 판은 **미확인**. 외곽선은 `text-shadow` 여러 겹으로 대체 가능하게 설계 |
| R6 | 같은 PC 에서 OBS 인코딩 + 이 앱 발표 창 + 배경 영상 → CPU 부담 | 이 기능 자체는 텍스트 SSE 라 가볍다. 전체 부담은 **미확인** |
| R7 | 포트 충돌(다른 프로그램, 앱 두 벌 실행) | 오류 표시 + 포트 바꾸기(Q2). 앱 두 벌이면 두 번째는 켜지지 않음을 알린다 |
| R8 | 방송 지연 때문에 OBS 자막이 관객 화면보다 늦어 보인다 | 송출 지연은 OBS 영상 전체에 같이 걸리므로 방송 시청자 기준 싱크는 맞다. 현장 모니터와 비교하면 늦어 보이는 것은 정상 |
| R9 | stt_translate 자막(통역)도 OBS 하단에 있으면 겹친다 | 디자인 '위치'로 비킨다. 둘을 한 덩어리로 묶는 기능은 범위 밖 |
| R10 | Windows 에서 127.0.0.1 전용 bind 가 방화벽 창을 띄우는지, 0.0.0.0(망 허용)이면 띄우는지 | **미확인**. 싱어 서버는 0.0.0.0 이라 처음에 묻는다(CLAUDE.md) — 망 허용 시 같은 안내 |
| R11 | 미리보기(Flutter)와 실제 페이지(HTML) 줄바꿈·크기 차이 | 싱어 화면과 같은 한계. '브라우저에서 열어 보기'로 실제 모습 확인 |
