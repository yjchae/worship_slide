# 휴대폰 화면 키 없는 고정 주소 + 발표자 PIN — 결과 정리

## 요구
- 휴대폰 싱어창·발표자 모드가 켤 때마다 바뀌는 키(토큰) 때문에, 발표를 다시 시작하거나 연결이 끊기면 다시 찍어야 했다.
  → 키 없이 `IP:포트` 주소로 누구나 쉽게 들어오게.
- QA 지적(누구나 발표 조작 가능) 뒤 사용자 결정: **발표자 모드에만 PIN 4자리**(PC 에서 정하고 발표자 폰에서 입력).

## 결과
| 화면 | 주소 | 들어오기 |
|---|---|---|
| 싱어창 | `http://<PC IP>:8765/` | 주소만 |
| 발표자 모드 | `http://<PC IP>:8765/presenter` | PIN 4자리 한 번(폰이 1년 기억) |

- 주소가 늘 같다 — 발표를 다시 시작해도 열어 둔 휴대폰이 저절로 다시 붙는다(SSE 가 닫히면 3초 뒤 다시 연다).
- 휴대폰 화면을 켜 둔 채('끄기' 안 누름) 발표를 끝내면 다음 발표 때 저절로 다시 켠다(앱 실행 동안만).
- PIN 은 `presenter_pin.txt`(처음 무작위), 휴대폰 화면 창 '발표자 모드' 탭에서 보고 바꾼다. 바꾸면 들어와 있던 폰도 다시 묻는다.
- 5번 틀리면 30초 잠금, 다른 웹 페이지(Origin 다름)의 POST 는 403.

## 남은 것
**사용자 결정(지금 상태로 써도 됨)**
1. PIN 강도 — 4자리·30초 잠금. 한 시간 예배 동안 대입으로 맞힐 확률 약 6%(QA 계산). 6자리로 늘릴지
2. '끄기'를 안 누르면 다음 발표 때 저절로 다시 켜짐 — 그대로 둘지

**알려진 작은 것**
- 예전 QR·즐겨찾기(`/?k=…`)로 열면 안내 없이 싱어창이 열린다(업데이트 직후 한 번)
- 터널(127.0.0.1)로 오는 사람은 PIN 잠금을 같이 쓴다 — 남이 5번 틀리면 쿠키 없는 발표자도 30초 막힘
- 쿠키 값이 PIN 그대로라 http 에서 엿보면 보인다(같은 망 한정)

**미확인**
- 실제 iOS Safari·안드로이드·카카오톡 인앱 브라우저의 쿠키 유지·재연결
- 실제 cloudflared 터널(Host 전달 — 터널 Origin 은 허용해 두었다)
- PC 앱에서 PIN 줄·바꾸기 창 실제 모양(위젯 테스트만)
- Windows·macOS 방화벽에서 같은 포트로 다시 켤 때
